# User documentation

For anyone who has to *run* and *use* this infrastructure — not modify it.
Developer topics are in [DEV_DOC.md](DEV_DOC.md).

---

## 1. What the stack provides

### Mandatory services — started by `make`

| Service | What it does for you | How you reach it |
|---|---|---|
| **nginx** | The single door into the infrastructure. Terminates HTTPS (TLSv1.2/1.3) and forwards PHP to WordPress. | `https://mozahnou.42.fr` |
| **wordpress** | The website itself: WordPress on php-fpm. | through nginx |
| **mariadb** | Stores every post, page, user and setting. | not reachable from outside, by design |

### Bonus services — added by `make bonus`

| Service | What it does for you | How you reach it |
|---|---|---|
| **redis** | Caches database queries so pages load faster. | internal only |
| **ftp** | Upload/download the website files directly. | `ftp://mozahnou.42.fr:21` |
| **adminer** | Web interface to browse and edit the database. | `https://adminer.mozahnou.42.fr` |
| **static-site** | A small showcase site about the project. | `https://static.mozahnou.42.fr` |
| **status** | A dashboard showing whether every service is answering. | `https://status.mozahnou.42.fr` |

## 2. Starting and stopping

Run everything from the repository root.

```bash
make              # start the mandatory stack
make bonus        # start the mandatory stack + the five bonus services
```

The very first run takes a few minutes: it builds every image from Debian,
downloads WordPress and creates the database. Later runs start in seconds.

```bash
make down         # stop and remove the containers — YOUR DATA IS KEPT
make stop         # pause the containers without removing them
make start        # resume them
```

To start again after `make down`, just run `make` (or `make bonus`) again. The
site comes back exactly as it was, because the data lives in volumes rather than
in the containers.

```bash
make fclean       # remove containers, images, volumes AND /home/mozahnou/data
```

> **`make fclean` deletes the website and the database permanently.** Use it
> only when you want to start from nothing. `make re` is `fclean` followed by a
> fresh build.

The first start also asks for `sudo` once, to add `mozahnou.42.fr` to
`/etc/hosts`. That is the only privileged step.

## 3. Visiting the website

Open **<https://mozahnou.42.fr>**.

The certificate is self-signed — it was generated by the nginx container for a
local domain, and no public authority can vouch for a `.42.fr` name. The browser
will warn you once; choose *Advanced → Continue*. This is expected and is not a
sign that anything is broken.

Plain `http://` is not served at all: only port 443 is published.

### The administration panel

**<https://mozahnou.42.fr/wp-admin>**

Log in with the administrator account (see §4). There are two accounts:

| Account | Role | What it can do |
|---|---|---|
| `site_owner` | administrator | everything: plugins, themes, users, settings |
| `mozahnou_editor` | author | write and publish its own posts |

### Bonus interfaces

- **Status dashboard** — <https://status.mozahnou.42.fr> — one page showing every
  service and whether it answers. Refreshes every 15 seconds. The same
  information as JSON at `/health`.
- **Adminer** — <https://adminer.mozahnou.42.fr> — log in with:
  system `MySQL`, server `mariadb`, username `wp_user`, password from
  `secrets/db_password.txt`, database `wordpress`.
- **Static site** — <https://static.mozahnou.42.fr>.
- **FTP** — host `mozahnou.42.fr`, port 21, **passive mode**, username `ftp_user`,
  password from `secrets/ftp_password.txt`. You land directly in the website
  directory. A file uploaded there is served by the website immediately.

## 4. Credentials

### Where they are

Every password lives in one file in the `secrets/` directory:

| File | Password for |
|---|---|
| `secrets/db_root_password.txt` | the MariaDB `root` account |
| `secrets/db_password.txt` | the `wp_user` database account (used by WordPress and Adminer) |
| `secrets/wp_admin_password.txt` | the WordPress administrator `site_owner` |
| `secrets/wp_user_password.txt` | the second WordPress user `mozahnou_editor` |
| `secrets/ftp_password.txt` | the FTP account `ftp_user` (bonus) |

Read one with:

```bash
cat secrets/wp_admin_password.txt
```

These files are generated with random values on the first `make`, they are
**never committed to git**, and they are given to the containers as Docker
secrets — mounted read-only at `/run/secrets/`, never as environment variables.

The non-secret settings (domain name, database name, user names) are in
`srcs/.env`.

### Changing a password

The passwords are consumed when a service is first initialised, so changing a
file is not enough on its own.

- **WordPress users** — change it in the admin panel (*Users → Profile*), or:
  ```bash
  docker exec wordpress wp --allow-root --path=/var/www/html \
      user update site_owner --user_pass='the-new-password'
  ```
  Then update `secrets/wp_admin_password.txt` so the file stays truthful.

- **FTP** — edit `secrets/ftp_password.txt`, then `docker compose ... restart
  ftp`. The entrypoint reapplies the password on every start.

- **Database passwords** — these are set when the database volume is created.
  Changing them afterwards means changing them in MariaDB *and* in
  `wp-config.php`; the simple path is `make fclean && make`, which regenerates
  everything from scratch (and erases the site).

## 5. Checking that everything works

### The quick way

```bash
make ps           # one line per container: it should say "Up"
make test         # the mandatory checks
make test-bonus   # the bonus checks
```

`make test` ends with a summary line. Anything other than `0 failed` deserves a
look — the failing check names the rule it was verifying.

With the bonus running, the status dashboard answers the same question visually:
<https://status.mozahnou.42.fr>.

### Reading a container's state

```bash
make ps                       # status of every container
make logs                     # follow the logs of all of them (Ctrl-C to stop)
docker logs wordpress         # one container's logs
docker logs -f nginx          # follow one container
```

A healthy `make ps` looks like this:

```
NAME        STATUS
mariadb     Up 3 minutes (healthy)
nginx       Up 3 minutes
wordpress   Up 3 minutes
```

### If something is wrong

| Symptom | Likely cause | What to do |
|---|---|---|
| The browser cannot find `mozahnou.42.fr` | the entry is missing from `/etc/hosts` | `make hosts` |
| A certificate warning | the certificate is self-signed | expected — continue |
| `502 Bad Gateway` | WordPress is still installing, or php-fpm is down | wait ~30 s, then `docker logs wordpress` |
| The site is up but has no content | the database was wiped | `docker logs mariadb` |
| A container keeps restarting | it crashes at start | `docker logs <name>` shows the reason |
| Port 443 is already in use | another web server is running on the host | stop it, or free the port |

Restarting one service is safe and quick:

```bash
docker compose -f srcs/docker-compose.yml restart nginx
```
